# PG24 Turnout Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** The 2024 general election (PG24) becomes a third certified turnout election: fetched from `press_room/2024_stats/PG24/`, parsed into `data/turnout/PG24/`, built into the db, published at `/turnout/pg24/` with figures of record only.

**Architecture:** The web/publish layer is generic — `ELECTIONS["PG24"]` + `certified=True` alone drive the slug, certified layout, `may_publish` filtering, data page, and source strips. All real work is pipeline: the file-set config, then parser support for whatever the 2024 exports print, validated against fixtures copied from the real files (the repo's parser-test idiom) plus the printed-totals reconciliation.

**Tech Stack:** Python (httpx, polars/calamine, pdfminer via `pdf_table_rows`), SQLite, FastAPI/Jinja2, pytest. Commands run through `uv run`; the CI gate is `uv run pytest -q -m "not slow"`.

    for family, geo_count in (
        ("early-voting", "County"),
        ("same-day", "County"),
    ):
        ...

### Task 3: Shape survey → per-family parser support (one family at a time, red → green)

**Files:**
- Test: `tests/test_turnout.py` (one fixture test per family, rows copied verbatim from the real 2024 lines — the `SD_*_ROWS` idiom: literal cells, small row-builder helpers)

**Per family, in this order** (each is its own red→green cycle + commit):

1. **requests** (`Mail-in Ballot Request Counts with Chart`): parse county rows to the
   delivery-method measures + total; assert exact values for two counties + the printed
   statewide total; the printed total must reconcile with the county sums or the parse
   fails.
2. **sent-returned** (xlsx ×3 grains): sent/received/accepted × DEM/REP/OTH/ALL; same
   acceptance criteria.
3. **county-canvass** + **votes-accepted** (pdf): the four modes + total per county;
   reconciliation: modes sum to the printed total, per county and statewide.
4. **mail-voting** (pdf): sent/received/accepted/rejected per county + the printed
   statewide row + the rejection-reasons block (its printed Total row must equal the
   reasons' sum).
5. **provisional** (pdf): cast/accepted-in-full/accepted-in-part/rejected + reasons block.
6. **official-turnout** (Updated-Official_by_Party_*): per party per county
   election-day/early-voting/vote-by-mail/provisional/eligible (Statewide block = `ALL`).
7. **eligible-active / eligible-inactive**: `active`/`inactive` per county per party.
8. **early-voting / same-day**: the eight-day day-columns + totals at all six grains,
   including the location grain's Grand-Total agreement checks (GP26's parser has these —
   reuse or adapt).

For each family:
- **Step 1:** write the fixture test with real copied rows and exact-value asserts; run → FAIL (or the 2026 parser errors/returns nonsense);
- **Step 2:** implement/adapt the parser — if the 2024 shape matches GP26's, no new parser: the fixture test simply passes (record that in the survey doc); if it differs, add a small variant keyed by what the document prints (a new `parse_*_pg24` is a last resort — prefer shape-agnostic helpers like the 2026 ones);
- **Step 3:** run `uv run pytest tests/test_turnout.py -q` → PASS;
- **Step 4:** commit (`git add tests/test_turnout.py src/skipjack/pipeline/turnout.py && git commit -m "pg24 <family>: parses as published"`).
