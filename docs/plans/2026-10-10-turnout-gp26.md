# GP26 turnout backfill — implementation plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task
> (or continue the established direct-implementation cadence from the first turnout increment:
> TDD per task, full suite green before each commit, two review passes).

**Goal:** Extend the turnout section to the 2026 primary (GP26) with every report family except
unofficial election-night turnout, reusing the machinery from the first increment.

**Design doc:** `docs/plans/2026-10-10-turnout-gp26-design.md` (read first — it tables every
family, its file shapes read from the live files, and the rules that carry over).

Ground rules (unchanged): TDD; ruff clean; data + archives committed; full `uv run pytest`
green before each commit that claims to be done; snapshots keyed by the document's own date;
reconciliation within one file only; percentages computed, not stored.

Implementation wave order (a task = TDD cycle + commit):

1. **Config**: GP26 in `ELECTIONS` (code, name, election day, file list — every family's
   URLs with xlsx preferred where both exist). Tests: the config table matches the live
   press-room inventory.
2. **Requests xlsx parser**: the GP26 requests workbook (reads cleanly; the GG26 twin stays
   corrupt and keeps falling back to PDF). Reconcile as `parse_requests_text` does.
3. **Official-turnout parser** (`official-turnout` xlsx, county/CD/LD): the six party
   blocks, `LBE`-headed rows, TURNOUT dropped (computed later), Eligible Voters stored;
   party labels mapped to the monthly codes with the block label (`Statewide` → `ALL`);
   per-block totals reconcile.
4. **Eligible parser** (`eligible-active` county/CD/LD/councilmanic + `eligible-inactive`):
   county x party columns + TOTAL block; parties as in the header (DEM/REP/GRN/OTH/UNA/WCP);
   reconcile parties == TOTAL.
5. **PDF-only families**: `county-canvass`, `votes-accepted`, `mail-voting`,
   `provisional` — extract_tables()-based county tables, counts reconciled per the shares
   printed beside them (share = count/county-total, re-computed and compared).
6. **Early-voting + same-day**: `extract_tables()`-based; day columns + the by-Party file
   (party × day × area) + totals; reconcile day sums == total.
7. **Left-to-count**: the sent-returned parser extended by one column (`left-to-count`).
8. **Ingest GP26 for real** (fetch → parse → build-db → sanity numbers against the printed
   totals; commit data + archives).
9. **Web**: `/turnout/gp26/` (final layout: turnout by party, ballots by mode, mail-in with
   rejections, provisional outcomes, early/same-day, denominators) + the index lists both;
   downloads/About follow automatically; db-backed pins.
10. **README + plan tidy-up** (`make turnout` unchanged; the daily workflow now also
    snapshots GP26's files forever — sha-dedupe keeps it cheap).

Known parsing risks to verify against the real files while ingesting: the official-turnout
blocks' county rows sometimes carry zero-everywhere rows (fine); the same-day PDFs'
`extract_tables()` header cell strings ("NEW\nDAY1"); the early-voting files' long share
columns; the votes-accepted second page's content.
